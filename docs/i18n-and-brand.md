# 双语(中文/英文)与品牌改名(OmniBot)

> 目标:界面支持中文与英文切换(英文兜底);所有用户可见的品牌统一为 **OmniBot**。
>
> 状态:**进行中**。基础设施与核心页面已完成并验证;其余页面按轮次继续翻译。

## 一、设计

### i18n 核心(`app/src/lib/i18n/`)

- `index.tsx`:`I18nProvider` + `useI18n()`(`{ locale, setLocale, t }`)。
- `zh.ts`:中文词典,**以英文字符串为 key**。

三条规则:

1. **英文即 key**。`t("Ask anything")` 查中文;查不到就显示英文。漏翻的页面显示原样,而不是 `missing.key`,翻译可以逐页增量。
2. **语言存在浏览器**,`localStorage["omnibot.locale"]`,与主题同一层:登录前就要生效,且是"这台机器上的阅读偏好"而非账号属性。首次访问跟随浏览器语言(zh* → 中文)。
3. **模板用具名占位符**。`t("Reached in {ms}ms", { ms })`,英文 key 里带同样的 token,翻译者能看到句子需要什么。

### 语言开关

`app/src/components/settings/language-preference.tsx`,放在「设置 → 通用」里,紧挨深色主题。切换即时生效(无需刷新)。

## 二、品牌改名

- 用户可见字符串里的 `OpenBot` → `OmniBot`,覆盖 `app/src`、`examples`(租户包提示词与 `brand.yaml`)、`shared`、`toolkit/src`、`worker/src`、`server/src` 的字符串与提示词;`server/src` 的注释未动(减少与上游的冲突面)。
- 小写标识符一律未动:`openbot`(租户 id、容器 id)、`@openbot/*` 包名、`OPENBOT_*` 环境变量、`openbot:` 前缀等。
- `examples/fintech/brand.yaml` 的 `product_name` → `OmniBot`,并重新生成 `app/src/lib/generated/application-config.ts`(首页与侧栏的品牌名来自这里)。

### 教训(已经发生并修复)

PowerShell 5.1 的 `Get-Content` 默认按 ANSI 解码 UTF-8,批量替换脚本因此破坏了 50 个含非 ASCII 字符(破折号、弯引号)的文件。
修复方式:上游未改动的 46 个文件用 `git restore` 还原后用 .NET UTF-8 重新替换;自己改过的 4 个文件(`server/src/index.ts`、`app.ts`、`copilot.ts`、`routes/_authed/_app/index.tsx`)用 GBK 反向还原(仅注释中个别破折号变为 `-`)。

**批量改源码必须用 `[System.IO.File]::ReadAllText/WriteAllText` + `UTF8Encoding($false)`。**

### 第二次事故(已修复,记录教训)

为给 4 个标签加翻译,我写了一条 PowerShell 补丁,把「替换对」当成了字符索引(`$pair[0]`/`$pair[1]`),
结果对 4 个文件执行了**单字符替换**:`a→r`(`clrssNrme`)、`{→o`(`oopen`),并误建了一个垃圾文件
`components/channels/message-scroller.tsx`。

修复:两个上游文件 `git restore` 还原后重新翻译;垃圾文件删除;详细核查后无其他文件受影响。
**教训:涉及多行/成对文本的批量替换必须用结构化脚本(哈希表/对象),不能用字符串下标。**
